# Firestore Database Schema

## Collection: `articles`

Stores news articles from both the existing API and those uploaded by journalists.

### Document Structure

```json
{
  "id": "string",                    
  "title": "string",                 
  "description": "string",           
  "content": "string",               
  "author": "string",                
  "userId": "string",                
  "thumbnailURL": "string",          
  "publishedAt": "timestamp",        
  "createdAt": "timestamp",          
  "updatedAt": "timestamp",          
  "status": "string"                 
}
```

### Field Definitions

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `id` | string | ✅ | Unique ID, generated by Firestore or client |
| `title` | string | ✅ | Article title (max: 200 characters) |
| `description` | string | ✅ | Short article summary (max: 500 characters) |
| `content` | string | ✅ | Full article content |
| `author` | string | ✅ | Author/journalist name |
| `userId` | string | ✅ | Firebase user ID (for permissions and audit) |
| `thumbnailURL` | string | ✅ | Cloud Storage image path |
| `publishedAt` | timestamp | ✅ | Publication date |
| `createdAt` | timestamp | ✅ | Document creation date |
| `updatedAt` | timestamp | ✅ | Last update date |
| `status` | string | ✅ | Status: "draft" or "published" |

### Indexes

To optimize frequent queries:

- **Composite Index**: `userId`, `status`, `createdAt` (descending)
  - Use case: fetch user articles filtered by status and date

### Security Rules

Security rules are defined in `firestore.rules` and ensure:
- Authentication required
- Users can only create articles with their own `userId`
- Only the author can edit/delete their own article
- Public read access to published articles (`status: "published"`)

### Cloud Storage

Image path: `media/articles/{userId}/{articleId}.{ext}`
- Example: `gs://newsapp-671e4.appspot.com/media/articles/user123/article456.jpg`
